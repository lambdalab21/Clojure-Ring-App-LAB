# Lesson 1A.5 — Handler Review Gate Before Jetty

Do this before Lesson 1B.

This is a short gate.

If you cannot pass this, Jetty will confuse you.

---

## The plain-English test

Explain this to a 10-year-old:

> A Ring handler is a function that takes a request map and returns a response map.

A good simple answer sounds like this:

> A handler is like a worker. You hand it an order ticket. It gives back a tray.

Now use the real words:

> The request map is the input. The handler is the function. The response map is the output.

---

## Gate 1 — Identify the parts

Look at this code:

```clojure
(defn handler [request]
  {:status 200
   :headers {"Content-Type" "text/plain"}
   :body "Hello"})
```

Answer:

1. What is the function name?
2. What is the parameter name?
3. What kind of value should `request` usually be?
4. What kind of value does the function return?
5. Which part is the response body?

---

## Gate 2 — Call it directly

In the REPL, call:

```clojure
(handler {})
```

Then call:

```clojure
(handler {:uri "/about"})
```

Answer:

1. Did the response change?
2. Why or why not?
3. Did Jetty call the handler?
4. Who called the handler?

Expected idea:

> The response did not change because this handler ignores the request.

---

## Gate 3 — Make the request matter

Use this handler:

```clojure
(defn uri-handler [request]
  {:status 200
   :headers {"Content-Type" "text/plain"}
   :body (str "URI = " (:uri request))})
```

Predict before running:

```clojure
(uri-handler {:uri "/"})
(uri-handler {:uri "/about"})
(uri-handler {})
```

Answer:

1. Which call gives `URI = /`?
2. Which call gives `URI = /about`?
3. What happens when the request map has no `:uri` key?
4. What did the handler read from the request map?

---

## Gate 4 — `{}` versus `nil`

Use maps for fake requests.

Good:

```clojure
(uri-handler {})
```

Better:

```clojure
(uri-handler {:request-method :get
              :uri "/"
              :headers {"host" "localhost"}})
```

Avoid this for normal practice:

```clojure
(uri-handler nil)
```

Reason:

> `nil` is not a request map. It may not crash immediately, but it can hide a weak test.

Answer:

1. Is `{}` a map?
2. Is `nil` a map?
3. Why is `{}` a better fake request than `nil`?
4. Why is a realistic fake request better than `{}`?

---

## Gate 5 — Request method practice

Use this code:

```clojure
(defn request-method-message [request]
  (case (:request-method request)
    :get "GET request"
    :post "POST request"
    "Unknown request method"))

(defn request-method-handler [request]
  {:status 200
   :headers {"Content-Type" "text/plain"}
   :body (request-method-message request)})
```

Predict:

```clojure
(request-method-handler {:request-method :get})
(request-method-handler {:request-method :post})
(request-method-handler {:request-method :delete})
(request-method-handler {})
```

Then run them.

Answer:

1. Why does `:get` return `GET request`?
2. Why does `:post` return `POST request`?
3. Why does `:delete` return `Unknown request method`?
4. Why does `{}` return `Unknown request method`?

---

## Gate 6 — Explain the future Jetty role

Later, Jetty will receive a real HTTP request.

The Ring Jetty adapter will build a map like this:

```clojure
{:request-method :get
 :uri "/"
 :query-string nil
 :headers {"host" "localhost:8080"}}
```

Then it will call your handler.

Answer:

1. In Lesson 1A, who made the request map?
2. In Lesson 1B, who will make the request map?
3. Does the handler idea change?
4. What changes when Jetty is added?

---

## Pass condition

You may move to Jetty only if you can explain this without notes:

> In Lesson 1A, I manually called the handler with a fake request map. In Lesson 1B, Jetty and the Ring adapter will call the same kind of handler with a real request map made from an HTTP request.

If that sentence is not clear, repeat this review gate.
