# 0B. From Raw HTTP to Ring Request Map

## Purpose

This lesson answers one question:

> What does your handler actually receive?

The answer is not “the raw HTTP request.”

The answer is:

> Your handler receives a Ring request map.

---

## 1. Feynman version

Imagine the customer says:

> I want the todos page, and I am asking for todo id 3.

That original order may be messy. The front desk and translator turn it into a clean ticket.

In web terms:

```text
raw HTTP request  →  Jetty parses it  →  Ring adapter creates request map
```

Simple version:

> Raw HTTP is the messy original order. The Ring request map is the clean order ticket.

---

## 2. Raw HTTP example

A real HTTP request may look like this:

```http
GET /todos?id=3 HTTP/1.1
Host: localhost:3000
User-Agent: curl/8.x
Accept: */*
```

Your handler does not receive this raw text.

Your handler may receive a Clojure map like this:

```clojure
{:request-method :get
 :uri "/todos"
 :query-string "id=3"
 :headers {"host" "localhost:3000"
           "user-agent" "curl/8.x"
           "accept" "*/*"}}
```

This is normal Clojure data.

---

## 3. Important keys

For now, focus on these request-map keys:

| Key | Meaning | Example |
|---|---|---|
| `:request-method` | HTTP method as a keyword | `:get` |
| `:uri` | path part of the URL | `"/todos"` |
| `:query-string` | part after `?` | `"id=3"` |
| `:headers` | map of request headers | `{"host" "localhost:3000"}` |

Do not try to memorize every possible Ring request key yet. That is fake progress.

Learn these four first.

---

## 4. URI and query string are separate

For this URL:

```text
http://localhost:3000/todos?id=3
```

Ring usually gives you:

```clojure
:uri "/todos"
:query-string "id=3"
```

Do not say:

```clojure
:uri "/todos?id=3"
```

That is the beginner mistake this lesson is designed to kill.

## 6. Valid HTTP request

Jetty checks the HTTP syntax before Ring sees the request.

Jetty handles things like:

- request line syntax
- headers
- body framing
- connection rules
- malformed HTTP

Feynman version:

> The front desk rejects impossible orders before the cook sees them.

If the request is badly formed, your handler may never run.

---

## 7. Debugging checkpoint

Answer these carefully.

1. If the handler never runs, should you first suspect the handler logic or the server/request path?
2. If the handler runs but returns the wrong body, should you first inspect Jetty or the handler logic?
3. Which layer parses raw HTTP?
4. Which layer creates the Ring request map?
5. Which layer reads `:uri` from the request map?
